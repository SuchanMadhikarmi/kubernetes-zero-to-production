# Security Policy

## Reporting a Vulnerability

We take security seriously. If you find a security vulnerability, please do not open
a public issue. Instead, report it privately to the repository maintainer so it can
be fixed before disclosure.

To report an issue:

1. Open a private issue using the GitHub "Report a vulnerability" flow, or contact
   the maintainer directly.
2. Include a reproduction, the affected files, and the impact.
3. Do not share the details publicly until the issue has been resolved.

## Scope

This repository is educational documentation and sample manifests. It contains no
production application code, but it does include example manifests that readers may
run in real clusters. Please follow the same reporting process for any dangerous or
misleading content you find in the documentation, labs, or examples.

## Response

- Initial acknowledgement: within 48 hours.
- Status update and fix plan: within one week.
